About this project

Automated CFG & MC/DC
Test Case Generation

A web-based tool that performs static analysis on Java source code to automatically generate control flow graphs and Modified Condition/Decision Coverage test cases — removing the need for manual test design in safety-critical software projects.

What is MC/DC?

Modified Condition/Decision Coverage (MC/DC) is a white-box testing criterion that requires each condition in a decision to be shown to independently affect the outcome of that decision. It was introduced by NASA and is mandated by the aviation software certification standard DO-178C for the highest levels of safety-critical software.

For a decision with N conditions, MC/DC requires a minimum of N+1 test cases. Each condition must have at least one pair of test cases in which it is the only condition that changes value, and that change causes the overall decision outcome to change. This guarantees that no condition is redundant in the decision logic.

MC/DC example — BankAccount.approve()

Decision: balance >= 0 && accountActive && withinLimit

How the tool works

The system uses a five-stage static analysis pipeline to go from raw Java source code to a complete set of MC/DC test cases.

1
Upload & validate — The Java file is received and validated for syntax correctness. Invalid files are rejected with descriptive error messages before any analysis begins.
2
Parse & build AST — The JavaParser library parses the source code and constructs an Abstract Syntax Tree, a hierarchical representation of every language construct in the program.
3
Construct CFG — The CFGBuilder traverses the AST and converts each statement, decision, and loop into nodes and directed edges, producing a complete control flow graph for each method.
4
Extract conditions — The ConditionExtractor identifies all decision nodes in the CFG and decomposes compound Boolean expressions into individual atomic conditions.
5
Generate MC/DC test cases — The MCDCGenerator applies the independence requirement: for each condition, it constructs a pair of test cases where only that condition changes and the decision outcome changes, annotated with a plain-language explanation.

Technology stack

The tool is built as a three-tier web application: a Java Spring Boot backend performing static analysis, and an HTML/CSS/JavaScript frontend rendering the interactive CFG and results.

Java + Spring Boot
Backend REST API, file handling, and all analysis pipeline logic
JavaParser 3.25
AST construction from Java source code via static analysis
D3.js
Interactive, zoomable, pannable SVG control flow graph rendering
HTML + CSS + JS
Frontend served as static files from the Spring Boot resources folder
Gradle
Build system and dependency management for the backend
JSON REST API
Communication layer between frontend and backend analysis engine
